Find out when AI assistants name you. And who they name instead.

Byname asks your questions where your buyers ask them, such as the ChatGPT app, Google AI Mode and Claude Code, on a schedule you set. It keeps every answer with its cost, counts who was named and cited, and puts your Search Console numbers on the same timeline.

MIT licensed. One container and your own Postgres.

What it does

Your questions. Your keys. Every answer kept.

Write the questions your buyers ask. Byname asks every one of them on every surface you pick, every few days, and tells you what changed since the last check.

01

Ask what buyers ask

Any number of questions in groups you name. Byname sends the raw question, never your brand name, and versions the set so history carries over when you edit it.

02

See who wins the answer

Every brand mention with its position, every citation, and the questions where an engine named a competitor and not you, ranked by opportunity. Compare any two checks down to the raw answer.

03

Tie it to search

Search Console straight from Google, read-only: daily clicks and impressions, brand against non-brand, top pages and queries, and goals with a due date.

Where people ask

What a person sees there, or labeled as not.

You pick surfaces, not engines. Each one is pinned to the endpoint closest to what a person sees, and every answer is labeled App answer, Same model and search, or Approximation. Labels are charted apart and never averaged together.

Approximations

The closest option where no app answer exists.

One Treg token runs every surface. Or bring your own DataForSEO, cloro or SerpApi key, an OpenAI, Anthropic, Gemini or Perplexity key, or an OpenAI-compatible gateway, surface by surface. See every surface and its pinned endpoint.

The boring parts

Built to run for months without you watching it.

No seats, no hosted dashboard, and no data leaving your infrastructure except the calls you turn on.

01

Bring your own keys

Provider keys and the Treg token are pasted in the app, encrypted at rest and never returned by any API. Only an Admin can set them.

02

Spend caps

A cap per check stops queueing calls once it is spent, and an optional monthly cap stops the next check from starting. Review shows the estimate first.

03

Runs itself

One setting: run checks every N days. The scheduler lives in the container, a redeploy never runs a check twice, and Search Console syncs daily on its own.

04

Every answer kept, with its cost

The raw response and the cost of every call. A call that reported no cost is flagged, never stored as $0, and each endpoint shows its success rate.

05

Mentions and citations apart

A link to your domain without your name is a citation, not a mention. Each gets its own number and its own chart.

06

One container

The web UI, REST API, MCP server and scheduler in one Go binary. Bring any Postgres. Migrations run on start and nothing is kept on disk.

Agents

Ask your agent which questions you lost this week.

REST and MCP call the same code as the web UI, so an agent sees what your team sees. Every key and connection carries scopes: read results, start checks, or change the setup.

MCP, signed in with OAuth

Add the URL to Claude Code, Cursor or Claude Desktop. Your browser opens, you pick the scopes, and the agent reads results as you. No key to copy.

# Claude Code
claude mcp add --transport http byname \
  https://byname.example.com/mcp

REST, with scoped keys

Create a key per script with only the scopes it needs, give it an expiry, and let it revoke itself if it ever leaks.

# Questions where a surface named someone else
curl https://byname.example.com/v1/gaps \
  -H "Authorization: Bearer $BYNAME_API_KEY"

Deploy Byname (https://github.com/unkeyed/byname) to Unkey for me, using Unkey's MCP server. Byname tracks how a brand shows up in AI answers and in Google search. The repository's docs/deploy-unkey.md is the reference for Byname's settings.

1. Connect to Unkey
   Check that Unkey's MCP tools are available (for example projects.listProjects). If they are not:
   - Claude Code: run  claude mcp add --transport http unkey https://mcp.unkey.com
     then tell me to run /mcp, choose unkey, and Authenticate. MCP tools load when a session starts, so if they still do not appear, tell me to restart the session and paste this prompt again.
   - Any other agent: tell me to follow https://mcp.unkey.com/install and stop until I say it is done.
   Signing in opens Unkey in my browser, where I can also create an account. Do every Unkey step below through the MCP tools.

2. Ask me
   For a Postgres connection URL (Neon, Supabase, PlanetScale Postgres, RDS or similar), ideally in AWS us-east-1. If the provider gives a read/write role and a separate admin role that can create tables, ask for both URLs.
   Do not ask me for a Treg token or provider keys. I enter those in Byname's onboarding after the deploy.

3. Fork Byname
   Run  gh repo fork unkeyed/byname --clone  and note the fork as owner/byname.

4. Create the project and app on Unkey
   - Create a project with slug byname (projects.createProject).
   - Create an app with slug default, sourced from my fork's default branch (apps.createApp with git.repository). If Unkey's GitHub App cannot see the fork, get the install link with github.installApp, give it to me, and retry once I have granted access.
   - On the production environment (environments.updateSettings): Dockerfile "Dockerfile", root directory ".", port 8080, health check GET /healthz, and regions set to us-east-1, or the region closest to my database, with 1 replica. The default region may be elsewhere, so set it explicitly.

5. Set production variables (environments.setEnvironmentVariables), every secret as writeonly
   - DATABASE_URL: the read/write URL.
   - ENCRYPTION_KEY: generate with  openssl rand -base64 32. Save it to ~/.byname-encryption-key with chmod 600 and tell me to copy it into my password manager. Unkey cannot show a writeonly value again, and Byname cannot read its stored provider keys and channel secrets without it.
   - SETUP_TOKEN: generate with  openssl rand -hex 32.
   - CLIENT_IP_HEADER: X-Forwarded-For. Unkey's gateway sets it to the real client address, so Byname throttles each client separately.
   Do not set PORT. Never print a database password, and never write a secret into the repository.

6. Migrations
   If I gave a separate admin URL, apply the migrations from the clone before the first deploy and keep the admin URL off Unkey:
     MIGRATION_DATABASE_URL='the admin url' go run ./cmd/byname migrate
   Otherwise DATABASE_URL must be able to create tables. Byname migrates when it starts.

7. Protect it at Unkey's gateway (gateway.setPolicies on production)
   - Firewall, deny: request paths matching dotfiles and secrets (/.env, /.git, /.aws, /.ssh), backups and keys (.sql, .bak, .zip, .pem, .key), PHP and WordPress probes (.php, /wp-admin, /wp-login, /xmlrpc.php, /phpmyadmin, /cgi-bin) and appliance scanners (/actuator, /server-status, /HNAP1), case-insensitive. Never block /.well-known/, /v1/openapi.yaml, /setup/, /invite/ or /auth/gsc/callback.
   - Rate limits per remote IP: ^/oauth/(register|authorize)$ at 30 a minute, and /auth/ at 120 a minute.

8. Deploy
   - Create a deployment on production (deployments.createDeployment) and follow it with deployments.getDeployment and deployments.listBuildLogs until it is ready.
   - Set PUBLIC_URL to the stable address without a deployment id, https://byname-<workspace>.unkey.app, then deploy again. Variables and gateway policies only apply to a new deployment, and passkeys only work at PUBLIC_URL.

9. Check and hand over
   - PUBLIC_URL/healthz and PUBLIC_URL/auth/setup/SETUP_TOKEN both answer 200, and PUBLIC_URL/.env answers 403.
   - Give me PUBLIC_URL/setup/SETUP_TOKEN to create the first account with a passkey. Tell me to add a second passkey under Settings > Account.
   - Tell me the next stop is onboarding: my brand and domain, competitors, questions, where people ask with a Treg token or my own keys, Search Console, and the schedule with spend caps. Nothing runs until I finish it.
   - Finish with a short summary: the URL, the Unkey project, the variables you set, where the encryption key is saved, and anything you could not do.

Or run it anywhere with Docker

Docker with Compose v2 starts Byname and Postgres 17 on your machine. Open the link it prints and register a passkey. Self-host Byname covers any other container host, and Deploy on Unkey covers every step by hand.

git clone https://github.com/unkeyed/byname.git
cd byname
echo "ENCRYPTION_KEY=$(openssl rand -base64 32)" >> .env
docker compose up -d --build --wait
docker compose logs app | grep -A2 'Open this link'
